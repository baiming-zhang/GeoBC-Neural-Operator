# Prepared coordinate-response delivery

One frozen first-registered-seed compact model served the same public JSON request handler across all 20 final CADs. Each CAD produced 60 new interior U/S rows at physical XYZ coordinates, with three explicit outside-domain refusals. All 1,200 interior responses were finite, and all 60 outside requests returned null fields. Registered loads remain ver/hor/tor.

Actual model load, prepared-input loading, location-index construction, requests and output cost: UTC 70.903s / monotonic 64.995s. One checkpoint and each CAD's geometry/physical-input body were loaded once; GT reads, training and scaler fits were zero.

This stage checks delivery from already prepared caches. Source construction, physical solves and model training are separate costs. It provides no new off-node finite-element truth, engineering accuracy, C1 continuity, arbitrary-load or changed-boundary-condition qualification. Final error conclusions are unchanged.
